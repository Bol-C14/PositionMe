# M0 — upstream integration and build baseline

Date: 2026-10-20. Target branch: `commit_back`. Integration source: `openpositioning/PositionMe:develop` at `591e07c05682e9acccd974b5bb6e4ca049c20a9b` (2026-03-04).

## Scope and decisions

The histories diverged by 11 upstream-only and 97 fork-only commits before this work. The merge preserves both histories and resolves 15 conflicted paths explicitly.

- Preserve fork bottom navigation, calibration, replay, EKF/PF fusion and JSON sensor capture. Keep the intentional deletion of the old HomeFragment/RecordingActivity flow.
- Integrate upstream sensor-state/event-handler/trajectory-recorder modules, foreground collection service, BLE and Wi-Fi RTT collection, updated trajectory schema and floorplan API support.
- Keep bundled Nucleus/Library floor maps as offline fallback and the existing building/floor UI contract. API vectors are used when available; network-only building data remains optional.
- Add a separate historical protobuf schema and adapter. Local old-format files remain unchanged; in-memory reads and uploads translate to the current schema. Reject malformed/unreadable uploads. Current-format data passes through unchanged. The legacy reader recognizes historical wire signatures; no general future-schema migration is claimed.
- Fix integration compile failures, gyro switch fallthrough, Wi-Fi input guards, optional RTT permission checks, startup initialization order and callback cleanup.
- Retain the existing singleton facade and UI coupling for M1 rather than treating upstream module extraction as completed OOP architecture.

## Build contract

JDK 17 in CI; locally verified with Microsoft OpenJDK 21.0.8 on macOS arm64. Gradle wrapper 8.11.1 with pinned distribution checksum, AGP 8.8.2, compile/target SDK 35, minimum SDK 28, Java source/target 17. Navigation plugin/runtime both 2.8.6; protobuf runtime/util both 3.25.3. Remove redundant secrets plugin, obsolete JCenter and conflicting duplicate test dependencies.

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
bash gradlew -Ppositionme.secretsFile=secrets.properties.example clean assembleDebug testDebugUnitTest lintDebug --console=plain
```

Empty example credentials deliberately isolate this check from local secrets. Actual maps/server use requires local configuration. Debug signing is generated by Android tooling. Release builds are unsigned until a separately managed signing configuration is supplied. Local credentials and keystores are untracked; their removal from the current tree does not erase existing Git history.

## Generated trajectory sources

Both checked-in Java outer classes are generated with protoc 3.25.3 (compiler reports `libprotoc 25.3`). Regenerate separately because the historical and current schemas intentionally reuse protobuf message names:

```bash
PROTOC=/path/to/protoc-3.25.3 bash scripts/regenerate-trajectories.sh
```

The script normalizes compiler trailing whitespace for repository checks.

## Limitations and release blockers

- M0 establishes an engineering baseline, not commercial release qualification. Real-device accuracy, battery usage, long sessions, screen-off behavior, denied/revoked permission flows and device diversity still require validation.
- Recording is in memory; process-death recovery/checkpointing is not implemented. The service must not silently restart as a recovered session. JSON snapshot capture still belongs partly to the recording Fragment; protobuf collection and JSON behavior differ in background.
- Existing recording startup UX automatically starts from Explore. Explicit user-controlled session ownership and reliable resume/stop semantics belong to M1/M2.
- Maps and online APIs were not validated with live credentials. The optional `tf_model.tflite`/`bssid2idx.json` assets are absent. API floorplan fetch/cache selection still needs end-to-end product wiring.
- The privileged master-key client configuration remains a release blocker requiring a server authentication design; removing tracked secrets is not sufficient. Review historical credential exposure with the credential owner.
- TensorFlow Lite 2.13 native binaries, 16 KB page compatibility, dependency updates, licensing, privacy/retention flows, release signing and distribution validation remain M4 work.
- Layout/accessibility/localization and existing lint warnings remain open. No positioning accuracy or performance improvement is claimed from this merge.
